# 从素材到介绍视频

| 阶段 | 产物 | 进入下一阶段的依据 |
|---|---|---|
| 明确目标 | 项目简报：对象、受众、目的、播放场景、片长与画幅 | 使用者确认；未定项明确标注 |
| 盘点素材 | 素材账：身份、尺寸、时长、可用区间、主要内容、限制和授权 | 实际查看和听取素材；说明与事实来源分开 |
| 主持词与脚本 | 稳定段落 ID、讲述、素材源入出点、动效用途、声音与字幕 | 使用者审核后录制；可按段录制 |
| 实录对齐 | 以实际讲述校对文字、专名和源时码 | 人工复听；自动转写只能作草稿 |
| 短样片 | 覆盖主要版式、画中画、观察停顿、音乐和字幕 | 使用者确认观看效果 |
| 全片 | 全片工程、新文件名 MP4、自动检查与人工审看记录 | 完整观看并试听，核对内容、字幕、同步、切换和导出要求 |

动效围绕内容安排。示例中的 18 秒、4 秒观察、标题字数和场景数量仅用于演示；不自动成为新项目规则。依据观众阅读和观察需要调整，不堆叠无信息作用的标签。

收到“修改 P03 的第二个镜头”时，先更新受影响脚本；素材映射改变时同步更新。按下面的影响范围确定检查量。保留原素材、使用的版本、渲染命令、成片和检查报告。

## 已验收版本的细小调整

**适用条件：**已有验收基线，只改一个元素的位置、大小、字号或颜色；素材、文字内容、时间轴、声音、共享组件和动效时序均不变。按实际影响判断，不按代码行数判断；字号变化造成换行或遮挡时，应扩大检查。

1. **定位：**记录基线版本、稳定段落 ID、时间段、目标元素及期望位置。默认按观看者视角描述左右，并补锚点或坐标；口径不同先统一。
2. **最小修改：**只读取相关项目规则、脚本和实现，复用已有核验记录；用源码差异确认范围，保留旧成果，在当前脚本追加一条修订记录。
3. **局部预览：**覆盖元素完整出现、退场及前后边界，原速播放并查看少量关键帧，核对位置、遮挡、字幕与过渡。通过后沿用已验证路径导出新版本；一次全片渲染可以作为默认方案，无须另造拼接流程。
4. **最终文件检查：**全片完整解码、规格与时长／帧数／时间戳核对、音轨内容及起止时刻与基线的一致性检查、修改处实际抽帧，可在一次任务中执行。若分段替换，还须检查拼接边界和音频连续性。未通过或没有适用的检查方法时，不能按已验证微调交付。
5. **交付：**简述改动、检查结果、未检查项，提供新成片和重渲染命令，交使用者验收。正常结果只报摘要，异常再展开日志。

满足以上条件时，不重复全片原速播放和逐段抽帧；局部预览不能代替最终文件完整性检查，也不代表重新完成全片主观验收。首次成片、内容／素材／时间轴／声音／共享组件／动效时序变化，或范围不明、检查异常时，恢复相应检查；首次成片及重大修改仍需全片观看试听。

**工具边界：**本节是流程规则，不是已提供的一键微调功能。`npm run verify` 只检查容器、编码、尺寸、时长和完整解码；帧数／时间戳连续性、音轨与基线一致性、局部预览和实际抽帧须另用适配本项目的方法核验。直接复制原音轨时可比对音频包；重新编码时可按相同解码条件比对 PCM，差异须查明。两种方式均须核对音轨起止时刻，不能仅以时长相同认定声音未变。

可用短会话执行后续微调，只携带基线、项目文件、段落／时间段、准确改动与约束。是否节省 token 取决于实际上下文和调用，不承诺固定降幅。

这些脚本不自动核实科普事实、匹配所有素材或检查口型。尚无主持人、旁白或准确时码时，不能以等分字幕时间冒充实际音画同步。

公开分享只处理经过确认的内容清单。新项目默认在被忽略的 `projects/` 下；发布时重新核对素材许可、第三方声明和实际 Git 提交，检查截图、日志和文件元数据中是否含私人内容。
